# Contributing to JL Aspect Works

Use the affected repository's issues for reproducible defects and scoped proposals. Include the repository/version, relevant platform, expected behavior, actual behavior, and safe reproduction steps. Do not attach credentials or private client projects.

Report suspected vulnerabilities privately using the [security policy](SECURITY.md), rather than public issue templates.

For changes:

1. Read the [standing development agreement](https://github.com/jl-aspect-works/engineering/blob/main/docs/DEVELOPMENT_AGREEMENT.md) and [coding standards](https://github.com/jl-aspect-works/engineering/blob/main/docs/CODING_STANDARDS.md), plus any repository-specific instructions.
2. Discuss material scope, architecture, compatibility, or design changes before implementation. Preserve locked decisions.
3. Work on a focused branch and open a pull request; do not change `main` directly.
4. Run applicable validation, add meaningful regression coverage, and report checks accurately. Monitor required CI through completion.
5. Resolve relevant security findings and review feedback. Obtain the applicable maintainer/user approval before merge.

Be respectful and constructive. Keep product licenses and branding usage terms repository-specific; these contribution guidelines do not grant additional rights to assets or software.
